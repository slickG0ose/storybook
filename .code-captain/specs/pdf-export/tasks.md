## Overview

Eight tasks split across server (5), shared (1), client (2), and one ADR-capture task. The natural sequence is **shared schema → server dependency + renderer → server route → server tests → client button → client test → ADR sweep**. Two parallel cuts exist: once Task 3 (the server route) lands, Tasks 5 (server tests) and 6 (client button) can be dispatched concurrently — different zones, no shared file. Task 1 (dependency install) is a CLAUDE.md guardrail-touch and MUST escalate to the user before running `npm install`.

The five "ADR-worthy decisions" the architect flagged are already decided in the spec and are implementation work for the developer (library choice, ephemeral PDFs, binary wire-shape carve-out, always-watermark, POST verb). Task 8 captures them after the feature is otherwise ready, in one batched ADR-authoring pass via `/create-adr`. The developer does not relitigate them.

## Cross-cutting constraints

Carried over from the spec — re-stated here so the developer doesn't have to context-switch back. **Do NOT duplicate the spec's reasoning; just the rules the developer must obey.**

- **Wire-shape (OPS.3 / ADR-003) — binary carve-out.** `POST /api/books/:id/pdf` returns a binary stream on 2xx, not JSON. The Supertest assertion shape for this route is:
  - 200 path: `expect(res.headers['content-type']).toMatch(/^application\/pdf/)` AND `expect(res.body.slice(0, 5).toString('utf8')).toBe('%PDF-')` AND `expect(res.headers['content-disposition']).toMatch(/attachment; filename=".+\.pdf"/)`.
  - 4xx/5xx path: `expect(res.body).toMatchObject({ error: expect.any(String) })` — matching `BookPdfErrorResponseSchema`.
  - The `validate()` middleware is mounted as `validate({ request: BookPdfRequestSchema })` only — no `response` key (response validation is opt-in; the binary stream has no JSON shape to pin).
- **Auth middleware order:** `requireAuth → validate({ request }) → handler`. Mount `requireAuth` first so unauthenticated callers get 401, not 400 (load-bearing — see `docs/conventions/server.md`).
- **Soft-delete default.** The book lookup MUST filter `deleted_at: null`. A PDF of a soft-deleted book returns 404. Reuse the existing pattern from `GET /api/books/:id` (also returns 404 for soft-deletes).
- **Draft authorization.** Mirror the existing `GET /api/books/:id` rule: published books require any authed user; drafts require `book.created_by === user.id`, otherwise 404 (not 403 — match the existing 404-for-not-yours convention; the spec's "403 or 404 — pick one and pin it" is resolved here as **404**).
- **Dark-mode parity (client).** The new "Download PDF" button needs `dark:` variants for every state (default, hover, focus, disabled, loading). Mirror the sibling `Publish` and `Add to Cart` button classes in `BookDetail.tsx`.
- **Accessibility.** Icon-only buttons need `aria-label`. The button text "Download PDF" already provides an accessible name, but if it goes icon-only at narrow widths, `aria-label="Download PDF"` is required.
- **TypeScript strict + no `any`.** `@react-pdf/renderer` ships with types; use them. If a typing gap surfaces, narrow with `unknown` + a guard, never `any`.
- **No new paid external API (CLAUDE.md guardrail).** `@react-pdf/renderer` is self-hosted on the existing Express server — no hosted PDF service. The dependency install itself still requires user confirmation (see Task 1).
- **Migrations:** none. The spec explicitly leaves the Prisma schema unchanged — no `pdf_url` column, no `PdfDownload` model. If the developer feels schema work is required, hand back to the architect rather than improvising one.
- **Guardrails touched:**
  - **Adding a new dependency** (`@react-pdf/renderer` on the server). Not a CLAUDE.md hard guardrail by itself, but the spec calls it out under Risks and the project's "Add a new paid external API" guardrail neighbors it. Task 1 escalates to the user before running `npm install`.

### Task 3 — Build the PDF renderer service (`server/src/services/pdf.tsx`)

**Zone:** server
**Depends on:** Task 1 (the library must be installed).
**Parallel-safe with:** Task 2.

**Files to add or change:**

- `server/src/services/pdf.tsx` — **new**. TSX because it holds React-PDF JSX. Exports `renderBookPdf(book: BookWithPages): Promise<NodeJS.ReadableStream>`. Imports `Document`, `Page`, `View`, `Text`, `Image`, `StyleSheet`, `Font` from `@react-pdf/renderer`.
- `server/src/services/pdf.tsx` also owns:
  - **Font registration** (`Font.register({ family: '<display-font>', src: <local-buffer-or-data-uri> })`) at module load. Use an open-licensed font (Atkinson Hyperlegible or similar — spec §Risks). Register once at top-level so it isn't re-registered per render. If the licensed font bundle can't be checked in, fall back to React-PDF's built-in `'Helvetica'` and log a one-line deprecation warning at module load (`console.warn('[pdf] Display font not registered; falling back to Helvetica.')`). Document the choice in the same file's header comment.
  - **Image fetching** — `<Image src={Buffer}>` per spread. Local `/illustrations/*` paths read via `fs.readFile(path.join('server/public', url))`. Remote `http(s)://` URLs fetch via `globalThis.fetch` with a 10s `AbortSignal.timeout(10_000)`. Never pass a URL directly to `<Image>` (deadlock risk — spec §"Data flow" + §Risks).
  - **Placeholder for missing illustrations** — when `page.illustration_url` is null, render a soft amber-cream `<View>` with the text "Illustration coming soon" centered. The route must succeed for partially-illustrated books (spec §Risks).
  - **Watermark abstraction.** Export the policy as a separate function with the signature `watermarkFor(book: BookWithPages): string | null` (default impl: `() => 'Created with StoryBook Storefront · storybook.example.com'`). The renderer's `<Page>` template imports `watermarkFor` and renders the band only when it returns a non-null string. PS3 will swap this function (or pass an override) without touching the page-template JSX. **Concrete bar for "abstracted enough":** swapping the watermark string to null per-book must be a one-function-body edit, not a `<Page>`-template rewrite. Watermark renders on interior story pages only — cover and end spreads are exempt (spec §Success criteria #3).
  - **Spread structure** mirrors `client/src/components/BookSpread.tsx`: cover spread (title + author + cover image or `cover_emoji`), N story spreads (illustration left / text right + page number footer), end spread ("The End" + description). Amber-cream paper tone (`#FFFBEB` background, `#1F2937` dark text). This is **intentional duplication** — do NOT import `BookSpread.tsx` (different reconciler, DOM-only).

**Signatures / shapes:**

### Task 4 — Add `POST /api/books/:id/pdf` route handler

**Zone:** server
**Depends on:** Tasks 2 and 3.
**Parallel-safe with:** none — Task 5 modifies the same test file and must run after this lands.

**Files to add or change:**

- `server/src/routes/books.ts` — add a new handler under `POST /:id/pdf`. Mounted as:

```ts
router.post(
  '/:id/pdf',
  requireAuth,
  validate({
    name: 'POST /api/books/:id/pdf',
    request: BookPdfRequestSchema,
  }),
  async (req: Request<{ id: string }>, res: Response) => {
    const user = res.locals.user as { id: string };

    // 1. Authorization — mirror GET /api/books/:id exactly:
    //    - 404 if no book or soft-deleted.
    //    - For drafts, 404 if user.id !== book.created_by.
    //    - For published, any authed user is allowed.
    const book = await prisma.book.findFirst({
      where: { id: req.params.id, deleted_at: null },
      include: { pages: { orderBy: { page_number: 'asc' } } },
    });
    if (!book) {
      return res.status(404).json({ error: 'Book not found' });
    }
    if (book.status === 'draft' && book.created_by !== user.id) {
      return res.status(404).json({ error: 'Book not found' });
    }

    // 2. Set headers BEFORE the renderer touches `res`. Once stream bytes flush,
    //    we can't switch to a JSON error envelope (spec §Risks).
    res.setHeader('Content-Type', 'application/pdf');
    res.setHeader(
      'Content-Disposition',
      `attachment; filename="${slugify(book.title)}.pdf"`,
    );

    // 3. Render + stream. Errors after the first flush are logged + the stream
    //    is destroyed (truncated PDF on the client — acceptable for MVP).
    try {
      const stream = await renderBookPdf(hydrateBook(book));
      stream.on('error', (err) => {
        console.error('[pdf] stream error:', err);
        res.destroy();
      });
      stream.pipe(res);
    } catch (err) {
      console.error('[pdf] render error:', err);
      if (!res.headersSent) {
        res.status(500).json({ error: 'Failed to render PDF.' });
      } else {
        res.destroy();
      }
    }
  },
);
```

- Import `renderBookPdf` from `../services/pdf` and `BookPdfRequestSchema` from `@storybook/shared`. Add a small local `slugify` helper (lowercase, non-alphanumeric → `-`, collapse, trim) inside the route module — do not import a slug library.

**Signatures / shapes:** see above. No schema changes; no Prisma changes; no new helpers exported.

**Tests to write:** Task 5 owns the tests. Authoring a stub here is wasted churn — write the route and the tests together in the next dispatch if the developer prefers, but the plan splits them so the wire-shape carve-out is reviewable in isolation.

**Manual verify (if applicable):** none at this layer; verify the full flow in Task 6.

**Done when:**

- `POST /api/books/:id/pdf` is mounted; `cd server && npm run build` succeeds.
- No new TS errors.
- `cd server && npm test` is still green (no regression — new route is not yet covered until Task 5).

### Task 5 — Supertest integration tests for the PDF route (binary wire-shape carve-out)

**Zone:** server
**Depends on:** Task 4.
**Parallel-safe with:** Task 6 (client) — different zone, different file.

**Files to add or change:**

- `server/src/routes/__tests__/books.test.ts` — append a new `describe('POST /api/books/:id/pdf', () => { ... })` block.

**Signatures / shapes (assertion patterns):**

```ts
describe('POST /api/books/:id/pdf', () => {
  // 200 + binary wire-shape carve-out (BOOK is published; any authed user can download)
  it('streams a PDF for a published book to any authed user', async () => {
    const token = await createUserAndGetToken(app);
    const res = await request(app)
      .post('/api/books/luna-star-garden/pdf')
      .set('Authorization', `Bearer ${token}`)
      .send({})
      .buffer(true)
      .parse((res, cb) => {
        const chunks: Buffer[] = [];
        res.on('data', (c: Buffer) => chunks.push(c));
        res.on('end', () => cb(null, Buffer.concat(chunks)));
      });
    expect(res.status).toBe(200);
    expect(res.headers['content-type']).toMatch(/^application\/pdf/);
    expect(res.headers['content-disposition']).toMatch(/attachment; filename=".+\.pdf"/);
    expect((res.body as Buffer).slice(0, 5).toString('utf8')).toBe('%PDF-');
  });

  it('streams a PDF for a draft to its owner', async () => { /* set status=draft, owner=user */ });

  // 401 unauthenticated — error envelope matches BookPdfErrorResponseSchema
  it('returns 401 without auth', async () => {
    const res = await request(app).post('/api/books/luna-star-garden/pdf').send({});
    expect(res.status).toBe(401);
    expect(res.body).toMatchObject({ error: expect.any(String) });
  });

  // 404 missing
  it('returns 404 for a nonexistent book', async () => {
    const token = await createUserAndGetToken(app);
    const res = await request(app)
      .post('/api/books/nonexistent-id/pdf')
      .set('Authorization', `Bearer ${token}`)
      .send({});
    expect(res.status).toBe(404);
    expect(res.body).toMatchObject({ error: expect.any(String) });
  });

  // 404 soft-deleted
  it('returns 404 for a soft-deleted book', async () => { /* set deleted_at, expect 404 */ });

  // 404 someone else's draft (the convention: 404 not 403 — matches GET /api/books/:id)
  it('returns 404 for another user\'s draft', async () => { /* status=draft, created_by=other, expect 404 */ });

  // 400 from validate() — strict request schema rejects unknown keys
  it('returns 400 when body has unexpected keys', async () => {
    const token = await createUserAndGetToken(app);
    const res = await request(app)
      .post('/api/books/luna-star-garden/pdf')
      .set('Authorization', `Bearer ${token}`)
      .send({ unexpected: 'key' });
    expect(res.status).toBe(400);
    expect(res.body).toMatchObject({ error: expect.any(String) });
  });
});
```

- Wire-shape assertion required: **yes (carve-out form)**. The 200 path asserts `Content-Type` + `Content-Disposition` filename pattern + `%PDF-` magic bytes. Every 4xx path asserts `toMatchObject({ error: expect.any(String) })` against `BookPdfErrorResponseSchema`.
- The `.buffer(true).parse(...)` chunked-collection pattern is required because Supertest's default JSON parser corrupts binary bodies — use it on every 200-asserting test in this block.
- The middleware-order check is implicit: the 401-without-auth case sends a malformed body too (`{}` is fine — the request schema is `z.object({}).strict()`, so the empty body passes). If the developer wants an explicit middleware-order smoke test, add one that posts `{ bad: 'key' }` without an `Authorization` header and asserts 401, not 400.

**Manual verify (if applicable):** none — covered by the integration tests at this layer.

**Done when:**

- All six assertions pass.
- `cd server && npm test` is green.
- No new TS errors.
