# Close the duplicate-account hole: case-insensitive unique `User.email` (citext) — task plan

> Spec: [spec.md](spec.md)
> Status: Approved (orchestrator ruling, 2026-10-31 — Nick away; see brief)
> Last updated: 2026-10-31

## Overview

Four tasks, all small and sequential: teach the generator to inject citext and regenerate the Postgres schema (1), pin it with a drift and loud-failure test (2), update the two docs that describe the gap (3), then file ADR-029 (4). Tasks 1 and 2 belong to one commit boundary. Task 3 is parallel-safe with 2. No SQLite migration, no route change, no UI.

## Cross-cutting constraints

- **Edit `schema.prisma`? No.** The SQLite schema is unchanged. All Postgres-only edits come from `server/prisma/gen-postgres-schema.mjs`. Never hand-edit `schema.postgresql.prisma`.
- **Never run `prisma generate --schema=prisma/schema.postgresql.prisma` locally.** It overwrites the SQLite client in `node_modules` and breaks the server suite. Validate with `prisma validate` only. If it happens anyway, recover with `cd server && npx prisma generate`.
- **No migration.** Nothing under `server/prisma/migrations/` changes.
- **Wire-shape / auth middleware / dark-mode / spend:** not touched.
- **Guardrails touched:** the auth identity becomes case-insensitive at the DB layer in prod; the session model does not change. `CLAUDE.md` gets a one-paragraph doc edit. Surface both in the PR body.
- **One server-zone agent at a time.** Server suites share `test.db`.
- **PR body must quote the exact DDL the next Render deploy runs:**
  ```sql
  CREATE EXTENSION IF NOT EXISTS "citext";
  ALTER TABLE "User" ALTER COLUMN "email" SET DATA TYPE CITEXT;
  ```
  It must also state that `schema.prisma` is unchanged by design, so the reviewer does not flag a missing SQLite migration.

### Task 1 — Generator injects citext; regenerate the Postgres schema

**Zone:** server
**Depends on:** none
**Parallel-safe with:** 3

**Status:** Done (2026-10-31)

**Files to add or change:**
- `server/prisma/gen-postgres-schema.mjs`: export a pure transform; add three exactly-once injections; write the file only when run as a script
- `server/prisma/gen-postgres-schema.d.mts`: declarations for the two exports, so Task 2's TS test compiles under `strict`
- `server/prisma/schema.postgresql.prisma`: regenerated by `npm run db:gen-postgres-schema`

**Signatures / shapes:**
```js
// gen-postgres-schema.mjs
export const HEADER; // the existing "DO NOT EDIT MANUALLY" header, unchanged
export function toPostgresSchema(sqliteSchema /* string */) /* : string */;
// Returns HEADER + transformed source. Throws Error naming the needle when any
// needle matches 0 times or more than once.

// Script entry, only when executed directly (not when imported by vitest):
if (import.meta.url === pathToFileURL(process.argv[1]).href) { /* read, transform, write, log */ }
```

The three replacements, applied to the SQLite source. Each needle must occur **exactly once**; count with `split(needle).length - 1`.

| # | Needle in `schema.prisma` | Replacement |
|---|---|---|
| 1 | `provider = "prisma-client-js"` | same line + `\n  previewFeatures = ["postgresqlExtensions"]` |
| 2 | `provider = "sqlite"` | `provider = "postgresql"` (existing swap) |
| 3 | `url      = env("DATABASE_URL")` | same line + `\n  extensions = [citext]` |
| 4 | `email         String    @unique` (User model, `schema.prisma:12`) | `email         String    @unique @db.Citext` |

Needle 4 must not match `customer_email` or `AllowedEmail.email` (`@id`). Its exactly-once check is what guarantees that. Needles 2 and 3 are the datasource; together they are the "extensions" injection.

```ts
// gen-postgres-schema.d.mts
export declare const HEADER: string;
export declare function toPostgresSchema(sqliteSchema: string): string;
```

**Tests to write:** none in this task (Task 2).

**Manual verify:**
- `cd server && npm run db:gen-postgres-schema`, then `git diff prisma/schema.postgresql.prisma` shows exactly three added/changed lines (previewFeatures, extensions, `@db.Citext`).
- `cd server && npm run db:gen-postgres-schema && git diff --quiet prisma/schema.postgresql.prisma` after committing, which proves the output is stable on a second run.
- `cd server && DATABASE_URL=postgresql://u:p@localhost:5432/x npx prisma validate --schema=prisma/schema.postgresql.prisma` reports valid. Do **not** run `prisma generate` against it.
- `git diff prisma/schema.prisma` is empty.

**Done when:** the three pieces are in the committed `schema.postgresql.prisma`, `prisma validate` passes, `schema.prisma` is untouched, and `cd server && npm test` plus `cd server && npx tsc --noEmit` are green.

### Task 2 — Pin the generator: drift check, citext pieces, loud failure

**Zone:** server
**Depends on:** 1
**Parallel-safe with:** 3

**Status:** Done (2026-10-31)

**Files to add or change:**
- `server/src/__tests__/postgresSchema.test.ts` (new): must sit under `src/**/__tests__/` to match `vitest.config.ts` `include`

**Signatures / shapes:**
```ts
import { readFileSync } from 'node:fs';
import { toPostgresSchema } from '../../prisma/gen-postgres-schema.mjs';
// Resolve schema paths relative to the server/ root (vitest cwd), e.g. 'prisma/schema.prisma'.
```

**Tests to write** (`server/src/__tests__/postgresSchema.test.ts`):
- **Drift:** `toPostgresSchema(readFileSync('prisma/schema.prisma'))` equals `readFileSync('prisma/schema.postgresql.prisma')` byte for byte. On failure, the message tells the reader to run `npm run db:gen-postgres-schema`. This is the first sync check in the repo. It also closes the "Schema-sync CI check" item in `docs/deploy-spike-render.md:229`.
- **citext pieces present** in the generated output: `previewFeatures = ["postgresqlExtensions"]`, `extensions = [citext]`, `provider = "postgresql"`, and a `User` model `email` line ending `@unique @db.Citext`.
- **Divergence direction pinned:** `schema.prisma` contains none of `citext`, `Citext`, `postgresqlExtensions`. SQLite would reject them.
- **Loud failure**, one case per needle: strip or alter each needle in an in-memory copy of `schema.prisma` and assert `toPostgresSchema` throws. Add one case where the `email` needle appears twice, which must also throw.
- **App-level guarantee: do not add.** `server/src/routes/__tests__/auth-normalization.test.ts` already covers lowercase-then-`NICK@` register returning 409 with one row (`:65`), mixed-case padded login (`:80`), and mixed-case register stored lowercase (`:29`). Leave it unchanged.
- Wire-shape assertion required: no (no route response changes).

**Fallback** if `tsc --noEmit` rejects the `.mjs` import despite the `.d.mts`: add a `--stdout` flag to the generator and have the drift test compare `execFileSync('node', ['prisma/gen-postgres-schema.mjs', '--stdout'])` against the committed file. Keep the throw cases by exporting the transform anyway. Record the choice in the hand-back.

**Done when:** the new test file passes and fails when you deliberately edit `schema.postgresql.prisma` by hand (check this, then revert). `cd server && npm test` and `cd server && npx tsc --noEmit` are green.
